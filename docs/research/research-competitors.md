# competitors

## Summary
Feature-matrix research on Mac fan-control/thermal apps as of July 2026. The market splits into: (1) proprietary controllers — Macs Fan Control (free core + $14.95 Pro that paywalls only saved custom presets), TG Pro ($10, threshold rules not curves, percent-based on Apple Silicon), iStat Menus 7 ($11.99, paid, has real temperature-ramped fan curves); (2) open-source monitors that can't or barely control fans — Stats (MIT, fan module officially in unmaintained 'legacy mode'), Hot, MacThrottle, Fanny (all monitor-only), smcFanControl (dead since 2016, Intel-era); and (3) brand-new open-source Apple Silicon controllers — ThermalForge (MIT, Apr 2026, fixed profiles + CLI + safety watchdog) and agoodkind/macos-smc-fan (MIT research repo documenting the Ftst diagnostic-mode unlock that defeats thermalmonitord's re-locking of fan mode). No app today offers free, user-editable multi-point fan curves with aggregate virtual sensors, history graphs, Shortcuts support, and a native SwiftUI UI on Apple Silicon — that is the winnable gap. Critically for the target machine, MacBookPro17,1 (M1, single fan) is NOT on the known list of models with hardware-restricted fan control (that list is M1 Max/M3 Pro/M3 Max 16" MBPs), so full forced-RPM control should work, subject to a firmware minimum-RPM floor (~1500 RPM observed on Apple Silicon; only Apple's automatic mode can reach 0 RPM).

## Key facts
- Macs Fan Control (CrystalIDEA, proprietary — its GitHub repo crystalidea/macs-fan-control contains only issue tracking and translation XMLs, no source): free tier includes real-time monitoring of all sensors incl. 3rd-party drive S.M.A.R.T., constant-RPM control, and single-sensor-based control (linear ramp between a start temp and a max temp against ONE chosen sensor), plus menu bar display of one sensor/fan. The ONLY Pro-paywalled features ($14.95 macOS, $24.95 macOS+Windows Boot Camp, one-time) are: creating/saving multiple custom fan presets (free is limited to Automatic, Full Blast, and one Custom config), priority support, and 'confidence in future updates'. Latest: v1.5.21, April 13, 2026; macOS 26 Tahoe dialog fixes landed in 1.5.19 (Oct 2025). UI is Qt cross-platform, not native SwiftUI.
- Macs Fan Control M1/Apple Silicon limitations (from crystalidea GitHub issues): #582 — app enforces a ~1500 RPM minimum on Apple Silicon (observed on M1 Max) while Apple's automatic mode can idle fans at 0 RPM; users requested a 'hand back to auto below threshold' hybrid mode, still open, milestone v1.6.0. #731 — on MacBookPro18,2 (M1 Max 16"), MacBookPro20,5/20,6/20,7 (M3 Pro/Max 16") firmware ignores fan-control writes while the system is cool; fans become controllable only once CPU/GPU warms (~60-70C). MacBookPro17,1 (target machine) is NOT on this list. v1.5.21 release notes say 'full fan control restored' on M3/M4 MacBook Pros, implying a firmware unlock workaround now exists.
- The unlock mechanism is publicly documented: agoodkind/macos-smc-fan (MIT, covers M1-M5) shows macOS's thermalmonitord daemon enforces fan mode 3 ('System Mode') and rejects direct SMC mode writes; a diagnostic-mode transition via the 'Ftst' SMC key sequence unlocks manual control. Its reference implementation is a Swift CLI (smcfan) -> XPC -> privileged helper daemon -> AppleSMC kernel driver. Caveat it states: shipping the privileged helper requires a paid Apple Developer ID for signing.
- TG Pro (Tunabelly, proprietary, $10 promo / $20 regular one-time; v2.103, March 19, 2026; macOS 10.13-26 Tahoe; supports M1-M5): on Apple Silicon/T2 the default modes are System / Max (all fans 100%) / Auto Max (threshold rules that jump fans to a percent of max when a sensor type crosses a temperature) — NOT continuous curves and NOT arbitrary RPM; rules are discrete thresholds, highest-percent rule wins. Setting arbitrary lower-than-system speeds requires an explicit 'complete override' option that removes the system's ability to boost fans (safety tradeoff). Extras: high-temp local notifications, email alerts, CSV logging, per-sensor menu bar display. No Shortcuts actions, no history graphs in-app.
- iStat Menus 7 (Bjango, proprietary, ~$11.99 single license + optional weather subscription, also on Setapp $9.99/mo; v7.3, macOS 11+): the only mainstream app with true temperature-ramped fan curves ('gradually ramp based on temperatures and battery state' with 'complete control over the speed curve'), replacing v6's discrete fan rules. Also has extensive history graphs, rules-based notifications across sensors, and deep menu bar customization. Paid and closed-source — no free tier.
- Stats (exelban/stats, MIT, 40.7k stars, v3.0.9 July 19, 2026, actively maintained by a single dev, 'open source but not open contribution'): best free menu-bar monitor (CPU/GPU/RAM/disk/net/battery/sensors widgets, charts, notifications, Apple Silicon sensor support), BUT its fan-control module is officially 'in legacy mode — no updates or fixes', kept only because it 'works pretty acceptable' on old Macs. This is the largest free competitor and it has explicitly abandoned fan control on modern hardware.
- smcFanControl (hholtmann, GPL-2.0, 2.5k stars): last release v2.6 on October 16, 2016 — effectively dead; only raises the MINIMUM fan speed above Apple defaults on Intel Macs; no meaningful Apple Silicon support. Historically important (its smc CLI is widely reused) but not a competitor anymore.
- Monitor-only free apps (no fan control at all): Hot (macmade/Hot, MIT, v1.9.4 July 2024, 3k stars) — CPU temp + thermal-pressure/speed-limit menu bar app with sensor graphs on Apple Silicon; MacThrottle (angristan, open source, active through late 2025) — thermal-pressure state via com.apple.system.thermalpressurelevel Darwin notifications + SMC core temp, 10-min history graphs, notifications, needs NO admin privileges; Fanny (DanielStormApps, free/open source, v2.3.0, stale) — fan RPM (actual/target/min/max) + CPU/GPU temp widget, monitoring only. 'Fan Menu' as a distinct product could not be verified to exist in 2026 — likely conflation with Fanny.
- ThermalForge (ProducerGuy/ThermalForge, MIT, v0.1.0 April 19, 2026, Swift, menu bar + CLI, M1-M5 on macOS 14+): the newest direct free competitor. Five FIXED fan profiles (Silent/Balanced/Performance/Max/Smart) with proportional curve shapes (quadratic ease-in, linear, S-curve), hysteresis, 100ms polling, per-chip-generation SMC key auto-detection, one-time-sudo privileged daemon. Safety design worth copying: 95C force-max override, crash-recovery heartbeat watchdog that returns fans to Apple defaults within 15s, automatic profile re-application after sleep/wake. CLI: status (JSON), max, auto, log (CSV/JSON thermal sessions correlated with top-5 CPU processes), discover (dump all SMC keys). Gap: profiles are hard-coded, no user-editable multi-point curve UI, no per-sensor rule targeting, v0.1 maturity.
- Universal Apple Silicon constraints every app has hit: (a) forced-RPM control cannot go below a firmware minimum (~1500 RPM class floor; 0 RPM idle is reserved for Apple's automatic mode) — a fan-off 'zero-RPM below threshold' mode is only achievable by releasing control back to auto; (b) taking manual control removes the OS's ability to boost fans itself, so the app must own the failsafe (TG Pro warns about this; ThermalForge solves with watchdog + 95C override); (c) Apple Silicon laptops power fans off in sleep and firmware may revert/hold state across sleep — Macs Fan Control had a bug where forced fan prevented sleep entry (since fixed), TG Pro exposes 'disable fan control when sleeping', ThermalForge reapplies profile on wake; (d) SMC fan/temp key names vary by chip generation, requiring per-model key discovery.

## Recommendations
- Win on curve editing: ship true user-editable multi-point fan curves (draggable points, per-point hysteresis, curve preview) driven by ANY sensor — nobody offers this free on Apple Silicon: Macs Fan Control free is a 2-point linear ramp on one sensor, TG Pro is discrete threshold rules, iStat Menus is paid, ThermalForge's curves are hard-coded profiles.
- Ship aggregate virtual sensors as curve inputs: hottest-of-CPU-cores, average-of-P-cores, max(CPU,GPU), moving-average smoothed variants. Macs Fan Control binds control to exactly one physical sensor — a frequent user complaint and an easy, visible differentiator.
- Ship a zero-RPM 'hybrid auto' mode: below a user threshold, release fan control back to macOS automatic (so the fan can idle at 0 RPM) and re-take control above it. This is Macs Fan Control's most-upvoted open request (issue #582, slated for their v1.6) — beating them to it is a concrete win.
- Copy and extend ThermalForge's safety architecture (it sets the 2026 bar): privileged helper daemon (SMAppService) with heartbeat watchdog that reverts to Apple-automatic within seconds if the UI app dies, hard force-max override at a critical temp (~95C), reapply-on-wake, and revert-to-auto on app quit/uninstall. Market this loudly — 'safe by construction' addresses the #1 user fear of fan apps.
- Add automation nobody else has: Shortcuts actions + AppleScript + a CLI (get temps/RPM as JSON, set profile/curve, revert to auto), profile auto-switching on power source, low battery, clamshell, or foreground app. Only ThermalForge has a CLI; no competitor has Shortcuts integration.
- Include temperature/RPM history charts (with sparklines in the menu bar popover) and CSV export — Macs Fan Control has zero history, TG Pro only offers raw CSV logging; combining live control with iStat-quality graphs for free is a clear gap.
- For the target MacBookPro17,1: expect full forced-RPM control to work (it is not on the restricted-model list in crystalidea issue #731), but design for the firmware min-RPM floor — show the real allowable range (min/max from SMC F0Mn/F0Mx) instead of letting users set impossible values; study agoodkind/macos-smc-fan for the thermalmonitord/Ftst unlock so the app is ready for models where plain SMC writes are re-locked.
- Positioning: 'everything Macs Fan Control Pro charges for, free' is the exact wedge — MFC's Pro paywall is only saved presets, so a free app with unlimited named presets + curves + history + Shortcuts + native SwiftUI (MFC is a Qt app) strictly dominates its free tier and its Pro tier simultaneously; pair with MIT/GPL open source and notarized releases to also outflank the abandoned smcFanControl and Stats' legacy fan module.

## Gotchas
- Distribution blocker: a privileged helper daemon for SMC writes must be signed with a paid Apple Developer ID certificate ($99/yr) — agoodkind/macos-smc-fan states free accounts cannot sign the helper; 'completely free app' still implies this developer-side cost, and Mac App Store distribution is impossible (SMC access is off-limits in sandbox), so plan on notarized Developer ID + Sparkle/GitHub releases + Homebrew cask.
- Fan-mode writes are actively fought by the OS: thermalmonitord re-enforces 'System Mode' (mode 3) and can reject/revert mode changes; robust control on newer firmware needs the documented Ftst diagnostic-mode unlock and periodic re-assertion — naive F0Tg/F0Md writes that worked on early M1 builds are not sufficient on all models/macOS versions.
- Model-dependent hardware lockouts are real and changing: M1 Max/M3 Pro/M3 Max 16" MBPs ignore fan writes when cool (crystalidea #731), and MFC 1.5.21 only recently 'restored' M3/M4 control — behavior can change with macOS/firmware updates, so the app needs graceful detection ('control unavailable right now') rather than silently failing. The target M1 13" is currently unaffected, but don't hard-code that assumption for other machines.
- Min-RPM floor: forced control cannot reach 0 RPM (approx. 1500 RPM floor observed on Apple Silicon in MFC threads); a 'quieter than Apple auto at idle' promise is physically impossible while holding forced control — only the hybrid release-to-auto approach delivers silent idle.
- Taking manual control disables macOS's own fan boosting (TG Pro documents this explicitly and gates it behind a 'complete override' consent) — the app, not the OS, becomes responsible for preventing overheat; a crash while fans are forced low is the catastrophic case the watchdog must cover.
- Sleep/wake edge cases have bitten every vendor: forced fan state once prevented Apple Silicon laptops from entering sleep (MFC changelog), fans power off in sleep regardless, and state after wake is undefined — must re-detect and re-apply (or release) on every wake and on fan-mode external changes.
- Sensor/fan SMC keys differ per chip generation (M1 vs M2/M3/M4/M5) and per model; ThermalForge does startup auto-detection and ships a 'discover' command for unknown hardware — plan a key-map layer plus a fallback sensor discovery path, and expect some sensors (e.g., certain M3 Ultra ones) to appear only after app updates, as MFC's changelog shows.
- Research caveats: 'Fan Menu' could not be verified as a real 2026 product (treat as nonexistent/renamed; closest match is Fanny, monitor-only); iStat Menus 7 exact pricing came from MacRumors coverage/comments (~$11.99-12) rather than a Bjango price page, which renders prices dynamically; TG Pro's $10 is a promo price (regular $20).
