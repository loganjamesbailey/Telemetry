# design

## Summary
Design-token spec for "Dieter Rams meets 80s neon": a dark-first system where ~90% of pixels are near-black violet-tinted neutrals (4 elevation steps: #0D0D12 / #14141C / #1B1B26 / #232330), ~8% are neon accents drawn from the real Synthwave '84 theme palette (cyan #36F9F6 primary for live data, magenta #FF7EDB secondary for fan/control, amber #FF8B39 warning, red #FE4450 critical, green #72F1B8 nominal/cool), and ≤2% is glow — produced by a 3-layer zero-offset SwiftUI shadow stack (radius 2/6/14 at opacity 0.8/0.5/0.25) applied ONLY to live data readouts, the active chart series, and momentary state-change pulses, never to chrome, labels, or buttons. Typography is SF Pro (Text ≤19pt, Display ≥20pt per Apple HIG) for UI and SF Mono for every numeral (RPM, °C) since SF Pro digits are proportional and would jitter on 1Hz updates. Spacing is an 8pt grid (2/4/8/12/16/24/32/48), hairlines are 0.5pt white@8%, corner radii 6/10/16 with ConcentricRectangle for outermost cards on macOS 26 Tahoe. Light mode swaps to Braun-paper neutrals (#F5F5F7/#FFFFFF), darkened accent ramps (e.g. cyan→#0A7C82), and kills glow entirely (honest design: no fake light without darkness). Grounded in Rams' ten principles (Vitsoe primary source — "unobtrusive", "honest", "as little design as possible") with Teenage Engineering as living proof the fusion works: strict functionalist chassis + one disciplined neon accent (RAL 2004 orange).

## Key facts
- DARK SURFACES (4 elevation steps, violet-tinted near-black so neons harmonize — derived from Synthwave '84's #262335/#241b2f/#171520 lineage darkened toward Tokyo Night's #1a1b26): bg0 window base #0D0D12, bg1 grouped panel #14141C, bg2 card/popover #1B1B26, bg3 menu/tooltip/hover #232330. Text on dark: primary #F2F2F7, secondary white 60% (#FFFFFF99), tertiary white 38% (#FFFFFF61). Hairline: white 8% (#FFFFFF14) at 0.5pt.
- NEON ACCENTS (from robb0wen/synthwave-vscode theme JSON, softened family — deliberately NOT pure #00FFFF/#FF00FF): accentCyan #36F9F6 (primary: live data, temps, focus), accentCyanDim #1FA8A5 (fills/gradients); accentMagenta #FF7EDB (secondary: fan control, selection, RPM), accentMagentaDim #A6518F; warnAmber #FF8B39 (approaching threshold), criticalRed #FE4450 (hot/over-threshold), successGreen #72F1B8 (nominal/cool). Each accent gets base + dim + glow(=base at shadow opacities) roles.
- USAGE RATIO DISCIPLINE (what keeps it Rams, not vaporwave): >=90% of screen area neutral surfaces+text; <=8% accent color, permitted only on data (chart series, live numerals, state icons, the active control); <=2% glow. Hard rules: max 3 glow-emitting elements per window; never two different accent hues glowing simultaneously (exception: multi-series chart, where only the hovered/focused series glows); accent never used on chrome, backgrounds, or decoration — every colored pixel must encode information (Rams: 'honest', 'unobtrusive').
- LIGHT MODE COUNTERPART (Braun paper, glow abolished): bg0 #F5F5F7, bg1 #FFFFFF, bg2 #FFFFFF + standard elevation shadow (black 12%, radius 8, y2), bg3 #FFFFFF + shadow(black 16%, radius 16, y4); text primary #1D1D1F, secondary black 60%, tertiary black 40%; hairline black 10% (#0000001A). Accents darkened for WCAG on white: cyan->#0A7C82, magenta->#B02E8C, amber->#C25E00, red->#D62839, green->#1D7A5C. Glow intensity forced to 0 in light mode — replace with 1.5pt solid underline/tint. Implement every token as Color(light:dark:) dynamic provider, never raw hex in views.
- TYPOGRAPHY: SF Pro Text for <=19pt, SF Pro Display for >=20pt (Apple HIG threshold; the variable font blends 17–28pt automatically when using .system). ALL numerals in SF Mono (monospaced = inherently tabular) or Font.system(...).monospacedDigit() for inline digits. Scale (macOS-native, 13pt body baseline): heroReadout SF Mono 36pt .light (big temp °C), readout SF Mono 20pt .regular (RPM), title SF Pro Display 20pt .semibold, headline SF Pro Text 13pt .semibold, body SF Pro Text 13pt .regular, sensorLabel SF Pro Text 11pt .medium UPPERCASE with tracking +0.6pt (Braun-style instrument label), axisLabel SF Mono 10pt .regular. Weight discipline: big numbers light/regular (thin = calm), bold reserved for critical alerts only.
- NEON-GLOW RECIPE (SwiftUI, layered zero-offset shadows): func neonGlow(_ c: Color, intensity: Double = 1) -> some View { self.shadow(color: c.opacity(0.8*intensity), radius: 2).shadow(color: c.opacity(0.5*intensity), radius: 6).shadow(color: c.opacity(0.25*intensity), radius: 14) } — tight core + mid halo + wide falloff reads as emission without bloom. For stroked shapes/chart lines use the stroke-blur technique (uvolchyk): sharp stroke lineWidth 2 + overlay stroke lineWidth 4 blurred 8 + second blurred layer at blurRadius/2 for saturation. Wrap glowing charts in .drawingGroup() to composite via Metal.
- GLOW POLICY: glow = 'this is alive or just changed'. YES: current temp/RPM readout (intensity 0.6 steady), active chart series line, threshold-crossing pulse (animate intensity 0->1->0.6 over 0.6s ease-out), fan mode change confirmation pulse. NEVER: window chrome, titles, labels, static text, icons, borders, sidebar, buttons at rest (hover may tint, not glow). Warning escalation: amber glow only after threshold crossed, red glow only in critical — glow absence is itself information.
- SPACING/GRID: 8pt base grid, 4pt half-step. Token scale: space2=2, space4=4, space8=8, space12=12, space16=16, space24=24, space32=32, space48=48. Card padding 16, related-row gap 8, section gap 24, window content margins 20. Strict column grid in dashboard: sensors in equal-width columns, numerals right-aligned on the tabular-figure axis.
- CORNER RADII & RULES: control 6pt, card 10pt, panel/sheet 16pt; on macOS 26 Tahoe use ConcentricRectangle / cornerRadius: .containerConcentric for outermost containers so cards nest concentrically inside the new rounder window corners (WWDC25 'Build a SwiftUI app with the new design'). Hairline dividers 0.5pt (1 device px @2x) in white 8%; no drop shadows between dark surfaces — elevation is encoded by surface step + hairline, not shadow (honest flatness).
- CHART STYLING (Swift Charts): horizontal gridlines only, max 4–5, hairline 0.5pt white 6%; axis labels SF Mono 10pt tertiary; series line 2pt with .interpolationMethod(.monotone) (no catmullRom overshoot — honest data); glow the line via neonGlow or duplicated blurred line; underfill LinearGradient [accent.opacity(0.28) -> accent.opacity(0)] top-to-bottom via AreaMark; threshold RuleMark 1pt dashed [4,4] amber, no glow until crossed; current-value PointMark 4pt circle with tight glow (radius 3 @ 0.9); temp series = cyan, RPM series = magenta, so the two core quantities are always hue-consistent app-wide.
- RAMS GROUNDING (Vitsoe primary source): the spec operationalizes principle 5 'unobtrusive — products fulfilling a purpose are like tools, neither decorative objects nor works of art' (=> neon only on data), principle 6 'honest — does not make a product more innovative, powerful or valuable than it really is' (=> no glow in light mode, no fake glass ornament, monotone interpolation), and principle 10 'less, but better — concentrates on the essential aspects' (=> 90/8/2 ratio, single glowing focus per region).
- REFERENCE POINTS (4, verified): (1) Synthwave '84 VS Code theme by Robb Owen — the canonical tasteful synthwave UI, source JSON supplies this spec's accent hexes; (2) Tokyo Night theme (enkia) — proof of restrained neon-on-near-black with a full light-mode counterpart palette (#1a1b26 dark bg, darkened light-mode accents like cyan #0f4b6e); (3) Teenage Engineering (OP-1/Computer-1) — the living Rams-heir brand: functionalist minimal hardware + one disciplined neon accent (RAL 2004 pure orange), the exact fusion this brief targets; (4) Braun/Vitsoe instrument design language via Rams' ten principles — uppercase micro-labels, strict grids, thin numerals, color only for function (Braun's single green/yellow dots).

## Recommendations
- Create DesignTokens.swift as three enums — Palette (all colors as Color(light:dark:) dynamic providers, with semantic names: .bgBase/.bgPanel/.bgCard/.bgOverlay, .accentData/.accentControl/.warn/.critical/.nominal — never expose raw hex names to views), Typo (static Font tokens incl. heroReadout = .system(size: 36, weight: .light, design: .monospaced)), and Metrics (spacing scale, radii, hairline = 0.5).
- Implement neonGlow as a ViewModifier taking (color, intensity) with intensity driven by state (0 = off, 0.6 = live-steady, 1.0 = pulse peak) and force intensity to 0 when colorScheme == .light — this makes the glow policy enforceable in one place rather than by convention.
- Adopt the 90/8/2 audit as a PR checklist item: any new view must justify each accent-colored element as encoding data or state; if a screenshot looks 'synthwave' at a glance, accent budget is blown — the ambiance should only be noticeable in the readouts and chart.
- Test glow performance early on the M1 with 1Hz sensor updates and a live-scrolling chart: three stacked .shadow() modifiers re-render per frame during animation; .drawingGroup() on the chart plot and pre-rendering steady-state glow (no animation while values merely tick) keeps CPU near zero for a menu-bar-class utility.
- Verify contrast with the actual pairs: #36F9F6 and #FF7EDB on #0D0D12 exceed 7:1 (fine); #FE4450 on #0D0D12 is ~5:1 — acceptable for the large critical numerals it is reserved for, but always pair state color with a text/icon change (Rams principle 4, 'understandable', doubles as color-blind accessibility).
- Use ConcentricRectangle for the outermost dashboard cards on macOS 26 so the app feels native to Tahoe's Liquid Glass geometry, but keep interior surfaces opaque token colors — translucent materials over a fan-curve chart would violate the honesty/legibility rule.

## Gotchas
- SF Pro digits are proportional by default: an RPM readout updating at 1Hz will visibly jitter in width (e.g. 1911 vs 2000 RPM). Every numeric readout must be SF Mono or carry .monospacedDigit(); right-align readout columns so the units column stays fixed.
- Do not use the pure meme-synthwave hexes (#FF00FF, #00FFFF, #191970): at 100% saturation on near-black they bloom on wide-gamut XDR-class displays and read as kitsch; the Synthwave '84 values (#FF7EDB, #36F9F6) are the battle-tested softened versions.
- Glow in light mode looks like a printing smudge, not light — there is no darkness to emit into. Kill it (intensity 0) rather than dimming it; substitute a solid tint or underline. This is also the Rams-honesty argument, so it needs no design debate.
- macOS body text is 13pt, not iOS's 17pt. Copying an iOS type scale makes a Mac utility feel bloated and non-native; the scale above is anchored to the 13pt macOS baseline.
- Stacked .shadow() modifiers are cheap statically but expensive when animated; animating glow on every sensor tick will burn CPU in a background utility. Only animate intensity on discrete state changes; steady-state glow should be static composited (.drawingGroup()).
- Swift Charts .catmullRom interpolation overshoots — a temperature curve can appear to exceed a threshold it never reached. Use .monotone for all thermal/RPM series (honest data presentation).
- The 4 dark surfaces are only ~3–5% luminance apart; on cheap external displays the steps can collapse. The 0.5pt hairline (white 8%) between surfaces is load-bearing, not decorative — never remove it when surfaces are adjacent.
- Hairlines must be 0.5pt only on 2x displays; on a 1x external monitor 0.5pt renders blurry — use max(0.5, 1/display scale) or round to 1pt at 1x.
